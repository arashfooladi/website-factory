# Website Factory

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The operator builds finished client websites. Clients receive the site on their own hosting and manage normal WordPress/WooCommerce operations, especially products and orders.

## Product Purpose

Turn a reference URL and client brief into a complete website through captured visual/source/interaction evidence, an AI builder, independent visual review, functional/admin testing, repairs and a restorable delivery.

## Confirmed Constraints

- MainTheme 0.4.0 WordPress parent and a clean child theme are the primary output; Next.js is a later profile.
- Support inspiration and scoped close replica work according to the client's brief.
- AI must inspect screenshots together with HTML, styles/geometry and observed flows. Bounded capture cannot establish unseen backend behavior.
- Keep business logic in plugins and preserve normal product/order administration.
- Run harsh desktop/mobile/awkward-viewport review independently from the builder, followed by protected functional/admin/commerce checks.
- Keep parent/reference/acceptance artifacts outside builder write access. Deliver the complete restorable site alongside clean client source.
- Continue development and routine pipeline decisions without waiting for intermediate approval. Record assumptions and stop for review when a real dependency or budget prevents completion.

## Current Evidence

Parts 1–6 are verified locally. The factory has a private API/CLI, isolated WordPress environments, an isolated Codex adapter, reference intake/capture and versioned design/MainTheme skills with protected design output. Full-site building, release QA, handoff, dashboard, production server deployment and additional output/providers remain later parts; see docs/PROGRESS.md.

## Open Decisions

Actual client brand/content, reference URLs, hosting details and integrations are per-project brief inputs. No global client visual identity or production hosting credentials have been provided.
