# Part 6 — design and MainTheme skills verification

Verified 2026-11-02 on the local Linux backend. **Part 6 is complete.** A representative brief produced a concrete, validated design direction and MainTheme implementation plan with exact instruction provenance.

## Delivered behavior

Three portable project-scoped skills cover reference analysis, client art direction and MainTheme implementation. The versioned manifest selects packages by role and pins its base-instruction file. Each run records names, versions, content/manifest hashes and the aggregate instruction hash; current runs retain the instruction bytes and explicit capability schema as private artifacts. Execution rejects changed instruction/provider configuration.

The skills adapt selected Impeccable 4.8.0 principles to the user's brief-driven autonomous workflow. They preserve client scope, distinguish inspiration from replica, require visual/source/flow evidence, define purposeful type/layout/imagery/responsive behavior and keep WooCommerce business logic out of child themes. Reference exploration does not silently add client features or integrations.

Reference-only analysts/designers can run without provisioning WordPress. They receive no live workspace/edit tools. A paired-state tool combines the screenshot, bounded HTML excerpt and structure summary to reduce redundant inference. Uploaded assigned assets are readable by hash-bound ID. Designer output must pass `factory_design`; prose alone cannot publish a plan.

The controller validates the intake/acceptance binding, required pages/checks/assumptions, actual evidence IDs and a matched screenshot/HTML/structure triple, client asset IDs, safe child paths, numeric tokens and readable body/control contrast. Successful output creates a protected structured record and DESIGN.md. Cancellation/expired authority/missing submission cannot publish it. Builders can bind that exact design together with the same intake.

Operational details: [design skills](DESIGN-SKILLS.md).
